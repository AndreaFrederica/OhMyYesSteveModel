# 通用网格运行库

本页记录[双后端决定](../product-decisions/decisions/dual-model-backends.md)下已实现的前置能力。完整宿主后端及剩余工作见[支持状态](../status/general-mesh-backend.md)和[后续方向](../future/general-mesh-backend.md)。MC 后端继续使用原有 bake/state/render 接口。

## Oh My YSM 的职责边界

项目正式名称为 **Oh My Yes Steve Model**，简称 **Oh My YSM**。`Oh My YSM Lib`（`ysm_runtime`）只负责与 Minecraft 无关的格式读取、场景求值、动画/物理会话、光影数据和通用几何输出；它不持有 Forge 实体、按键、GUI、模型 catalog、网络会话或 GPU 生命周期。UI 操作、Alt+Y 页面、模型选择与应用、Minecraft 实体/相机/第一和第三人称 pass、Forge/其他 Mod 兼容均属于主 Mod 的宿主层。

当前为兼容已有模型、协议、资源命名空间和扩展，`ysm` mod id、`assets/ysm` 和 `com.elfmcys.ysm` Java 包名继续保留；显示品牌使用完整名称，后续若要切换新的 mod id 必须单独提供迁移与联机兼容方案。

## 资产与来源

`SceneProvider` 是普通 Java 服务入口，由 Oh My YSM Lib 的 `YsmRuntime.scenes()` 提供。接口、不可变资产和类型化 MMD 文档位于 `scene-api`；Java 场景求值、glTF 与 MMD 读取分属独立模块。算法模块不依赖 Minecraft、Forge 或图形上下文。

读取器拥有源数据副本，公开只读视图。glTF 场景保存完整节点树、独立 skin joint 集合、逆绑定矩阵、材质、纹理、镜头与光源。PMX 和 PMD 各自保留类型化原文档，防止 PMD 基础表情间接索引、相对骨骼的刚体位置等差异在投影前丢失。原始文件与依赖内容可供归档和扩展使用。

外部依赖必须经过调用方提供的 `AssetResolver`。读取器不自行打开网络或宿主路径；目录解析器检查 URI 解码后的相对路径及真实路径归属。读取受源字节、累计元素及解码数据预算约束。损坏引用、循环层级、截断记录和重复 JSON 字段均明确拒绝。

`ScenePackage` 把原模型、动作和依赖保存在不可变封闭归档中。Lib 负责有界读写及按 owner 解析路径；URI 与 DCC 字面文件名使用不同解析策略，显式重定位不赋予外部文件访问能力。包结构、源文件语义、运行求值和绘制分别验收。规范见[场景包与通用网格 Schema](../standards/scene-package.md)。

`loadPackage` 组合各格式读取器，保存类型化来源与依赖映射；PMM1 的骨架结构来自包内重定位后的 PMD/PMX。PMM 配件和媒体也必须存在，但当前仅保留其字节，不把文件存在视作媒体解码或多对象运行已完成。

宿主按独立 schema 分派 target definition，MC 仍读取 `ModelData`，通用网格读取场景包。两者共用现有容器身份和 metadata prefix；导出沿用来源 schema，避免复制制品时更换后端。远端按 definition 请求场景包；完整资源发布与渲染仍在接入，状态以支持页为准。

场景图片通过独立解码入口输出原始传递函数下的浮点 RGBA，不借用旧 MC 的 RGBA8 wire。PNG 的高精度与灰度样本直接保留，BMP 按实际内容识别，TGA 保留透明度关联方式并处理原点、交错行和 RLE。解码不自行施加显示用的 gamma/ICC、预乘或色调映射；颜色与数据纹理的解释由材质用途决定，原文件继续可访问。

场景包图片按所属模型与来源索引/字面路径寻址，PMM 子模型使用重定位后的模型路径。完全相同的内容共享不可变解码数据，材质 sampler、UV 与传递函数仍独立。图片加载在每图预算之外累加唯一图片的像素和存储预算；解析依赖成功不意味着图片已解码。当前解码范围与限制见支持页。

材质通过明确的图片用途选择线性/sRGB 和 alpha 解释，传递函数在插值及 mipmap 生成之前处理。同图不同 sampler 对应不同宿主纹理；同图同用途可以共享不可变 CPU 样本。宿主以浮点纹理上传并保留完整 mip 链，后台准备和 GPU 存储分别有累计预算。发布失败或取消撤销该次已采用的映射，成功后的 binding 交由 target owner 统一清理。

通用 payload 的后台阶段由 Lib 读取场景包、准备初始完整视图和材质样本，短期播放探测使用私有会话并立即关闭。既有 ModelCandidate 在 render owner 发布共享程序及所有纹理；成功前不暴露可绘制状态，失败回收本次程序和映射。ModelRenderTarget 的同一清理 action 释放该 payload；consumer lease 不获得共享资源的物理关闭权。此发布分支已完成独立验证，完整加载入口及消费者分派仍以支持状态为准。

GeneralMeshInstance 由实体或预览 consumer 独占，拥有 Lib 播放器、时间轴、物理和网格流式缓冲，借用 target 程序/纹理。新动作会话成功取得初始帧后才交换；失败维持上一动作。绘制只读取已发布帧，关闭一个实例不关闭共享 target。该实例必须由 consumer 的既有 lease 保活，不能形成第二套共享资源管理。

客户端 render-target manager 持有一份按需创建的场景 render host，复用浮点合成缓冲；实体不各自分配整屏缓冲。该 host 不保存模型内容或播放权，进程关闭由原 host executor 释放。默认适配器读取当前实际绑定的颜色与深度附件，覆盖普通游戏目标和私有预览目标；不假设所有绘制都进入 main target。RGBA8 显示数值先转为线性浮点，再绘制 glTF 并转换回显示数值；alpha 不做颜色转换，深度/模板随成功绘制提交。source/draw 失败不提交目标。MMD 的 SOURCE_NUMERIC pass 直接使用对应数值空间。

独立 `RenderSceneEvent` 在 queued host geometry flush 后提供不可变资产、已求值双视图帧与相机空间输入。扩展可以修改当前视图，或取消默认 pass 并在分派期间借用材质绘制；回调在分派结束后失效，不能异步保存。帧中保留的来源镜头、灯光与阴影轨道不等于内建效果绘制。多附件、MSAA、shader-pack 工作空间与阴影 pass 必须由明确的扩展适配，不能把普通 RGBA8 转换误用到它们。实体入口接入与验证状态见支持页。

普通世界和第一人称的通用模型采样 Minecraft 实际上传的 16×16 光照贴图，方块光与天空光独立作为 texel 坐标传递。天空光等级表示天空可达性，不能用 `max(block, sky) / 15` 代替昼夜亮度；光照贴图已经包含昼夜、天气、维度、亮度设置、夜视与黑暗效果。`SceneView.lightmap` 仅借用当前 draw 的 GPU 纹理，随节点及 MMD/glTF/VRM 材质视图传递，不复制到 Lib、缓存或播放状态。绑定使用材质纹理之外的一个 sampler，绘制结束和绑定失败均恢复宿主纹理、sampler、活动单元及程序。

MMD 的 diffuse、ambient、specular、sphere 与描边在来源数值空间接受游戏光照；glTF/VRM 将光照贴图显示数值转为线性值后作用于受光表面。材质明确声明的 unlit 和自发光保留原语义，VRM 描边按其 lighting mix 接受光照。Alt+Y、编辑器与纸娃娃使用独立预览照明，不借用世界光照贴图。此接入属于普通 Minecraft 环境照明，与来源灯光/阴影轨道的扩展机制分别处理；shader-pack 仍需要显式宿主适配。

PMM 是独立的多对象工程文档，保留模型与配件关键帧、外部亲、镜头、光影、重力、媒体引用、编辑器状态和未知尾部数据。PMM 1 的轨道数量与名称来自调用方提供的原模型结构；PMM 2 使用工程内的声明。工程路径通过显式文件映射或源目录映射重定位到当前资产能力范围；外部工作站绝对路径不直接用于文件访问。

VRM 使用建立在 glTF 文档之上的独立版本配置。VRM 0 与 VRM 1 分别保存人形骨架、表情、第一人称、视线、材质及弹簧定义；旧版百分比权重、shader 属性、曲线和子树弹簧不会被静默替换为新版语义。原始元数据与扩展仍可从源文档访问。

FBX 使用固定 ufbx 的托管 WASM reactor。源文档保存原始字节、双精度角点与矩阵、动画层和原曲线、版本化材质数据、morph 中间形状及原始路径。公共类型不持有可变 JSON 或 reactor 内存。读取限制覆盖全部传输值与容器；外部图片仍由调用方的解析能力提供，文件中的绝对路径不授予访问权。

## 求值与变形

`SceneEvaluation` 将指定时间映射为拥有独立数据的 `ScenePose`。所有节点均参与层级计算；一个节点是否属于 skin 不影响它的存在与动画。glTF joint palette 由网格节点逆矩阵、joint 全局矩阵与源逆绑定矩阵组成。

曲线保留 STEP、线性、Hermite 三次样条和 MMD Bezier。四元数线性通道使用最短弧球面插值；glTF 三次四元数采用分量 Hermite 后归一化。MMD Bezier 先反解横坐标，相邻一帧的镜头关键帧保留切镜语义。采样与墙钟及前一次调用无关。

BVH 保留原始 Euler 通道顺序、End Site 和采样周期，按原通道线性插值或逐帧保持，再组合层级矩阵。完整旋转不会先压缩为四元数关键帧；位置通道与骨骼 offset 相加。BVH 的单位和坐标系由调用方提供，不按文件扩展名猜测。PMM 内嵌动画采用每秒三十帧，编辑器显示帧率不改变动作时间；场景专属通道随编译结果保留。

CPU 变形先执行 morph 再蒙皮，支持任意数量的 influence 集合和 morph。MMD 稀疏 morph 只保存实际偏移，不为每个表情复制全网格。SDEF 保留并使用原始 C/R0/R1，QDEF 使用双四元数；两者要求刚性骨骼变换。glTF 和 MMD 的法线规则明确区分，不能用 LBS 替代 SDEF/QDEF。

glTF 表面准备在 morph/skin 之前生成缺失的平面法线和默认 MikkTSpace 切线，法线贴图可指定任意 UV 集。每个 morph 目标分别生成对应增量，切线 W 不参与 morph；作者已有法线/切线保持其源规则。生成结果按三角形角点保留，拆分时复制全部属性与 skin influence，不用旧索引覆盖 UV 镜像边界。此过程生成独立几何且有累计预算，原始资产不变；VRM 可见性筛选在完整网格准备之后执行，避免第一人称删除面改变剩余面的切线。

MMD 运行时拥有独立的 morph、骨骼、IK 和物理调度。PMX 按物理前后、变形层与源顺序求值；PMD 保留自身骨骼类型、膝盖约束、旋转继承与 IK 顺序。名称绑定、固定轴、继承、组合/翻转/骨骼/材质/冲量 morph 参与同一结果，输出兼容诊断。具体跨工具验证范围见支持状态。

VRM 表情从不可变基值组合 morph、材质和纹理变换，按二值输出计算程序表情覆盖。同类表情之间的同类覆盖无效，matcap 不参与 UV 变换绑定。节点约束显式接收局部旋转，依赖图区分局部旋转和世界变换读取；求值保留原矩阵中的缩放，不通过分解世界矩阵替代源变换。

VRMA 从源静止姿态建立人形世界旋转变化，再映射到目标静止轴与局部空间。源端可选骨骼影响会补偿到目标下游分支；髋部位移显式按高度比例或调用方比例缩放。多个动画与未绑定表情诊断保留，不以固定帧率烘焙替代原曲线。

第一人称几何按节点和实际 skin 映射生成独立可见索引。头部及后代的任意正权重会剔除所在图元；刚性附件按节点祖先判定。输出保留源 primitive 编号与顶点空间，三角带展开保持绕序，线段删除不重连；另一视图及其他节点实例仍使用原资产。

材质数据与宿主 shader 分离。MToon0 保留源 shader 色彩值、额外纹理、keyword、绘制队列和独有参数，不进行有损新版转换。纹理 UV 使用统一的 glTF 顶部原点，旧版求值显式转换滚动/旋转方向、次序及单位。旧 importer 的 mask 纹理传递函数也与新版分开。MToon1 缺省 shade 采用 schema 的白色，并诊断其与规范正文/three-vrm 黑色默认之间的差异；显式源值优先。其他材质扩展和自定义 shader 保留并报告求值缺口。

FBX 求值保留 pivot、缩放继承和原动画层，不先重采样成 glTF 轨道。网格实例独立输出完整权重变形、作者角点法线与 UV 方向，再显式转换为共享绘制网格。材质索引来自实例；绘制帧中的几何已经变形，宿主不重复蒙皮。世界绑定和基于 bind pose 的网格节点运动补偿是两种显式源工作流设置。无法表达的形变、约束与几何种类由播放接口明确拒绝；具体支持边界见支持状态。

## 物理与扩展

MMD 材质通过独立的来源定义与最终 morph 参数交给宿主。贴图乘法/加法各自保留四个分量，因其中的 alpha 控制颜色混合，不能用普通 RGBA 乘加代替。PMD 保留字面贴图路径；包内默认 toon 同名文件优先，只有缺失的标准默认名可回退到 Lib 的固定资源。PMX 的共享 toon 使用独立图片域，不与模型纹理索引混淆。损坏覆盖文件与缺失自定义路径仍失败；内置图片也计入解码与上传预算。

材质选择的工作空间不总是物理线性空间。glTF 的 sRGB 颜色纹理在线性化后过滤；MMD 的传统 shader 使用显式 `SOURCE_NUMERIC` 保留原编码数值参与过滤和颜色运算。后者不能被解释为 glTF PBR 的线性颜色；宿主传统材质 pass 也不重复施加 framebuffer sRGB 转换。

PMX 2.1 的点/线绘制在已求值几何上生成独立绘制索引，原三角形和全部顶点属性保持可访问。线绘制包含每个三角形的三条边，点绘制优先于线绘制；额外索引受预算约束。附加 UV 子纹理和顶点颜色明确要求完整 UV1，缺少时不能用 UV0 代替。

`GeometryFrame` 是已变形几何与实例矩阵的共享投影。普通场景和 VRM 按节点选择场景、skin 与视图；同一 mesh 的刚性实例不继承其他实例的 skin。MMD 的普通帧携带已经完成的形变；宿主选择 compute 时，帧显式标记未变形，并保留同一姿态的 palette/morph 供实例渲染器解析。其他格式和已变形 MMD 帧不得二次变形。FBX 从每个实例的求值结果投影；编译几何不推进时间或物理。

宿主网格缓冲由绘制实例独占，使用真实的索引拓扑。shader 以属性语义指定所需输入位置，UV 集不固定为第一组；缺失或超出硬件能力的输入明确拒绝。上传和绘制恢复借用的 GPU 绑定及 primitive restart 状态；缓冲不推进播放时间。材质 shader、实体分派与预览接线仍以支持状态为准。

普通世界和 GUI 的正反面判定同时计算模型视图的三维手性及投影 XY 平面的方向，深度映射符号不参与屏幕绕序。Minecraft GUI 的 Y 向下正交投影会翻转屏幕绕序，MMD/glTF/VRM 均通过同一 SceneWinding 规则处理。MMD 像素描边的法线方向也先投影到屏幕像素空间，再按源 edgeSize 挤出；否则 GUI 中会向表面内部扩张黑色描边。此适配保留源材质/贴图数值，不通过提高亮度或移除背面剔除掩盖问题。

glTF 材质程序按完整视图所需的属性变体预编译并由 target 共享；隐藏图元仍参与变体发布。实例绘制在首个 draw 前校验整帧源材质、纹理引用、实际纹理 ID、变换与几何预算，冻结本帧绑定；原映射不接受未经发布的新纹理引用。opaque/mask 先写深度，blend 按相机空间包围范围中心稳定地从后向前绘制且不写深度；相交透明面仍受图元级排序限制。节点变换的负行列式参与绕序与切线手性。线性 glTF 输出在 sRGB 目标上启用一次 framebuffer 转换，普通数值目标的最终合成由宿主负责。

`AnimationPreview` 拥有一个时间轴与确定性 seek 源。宿主每次更新传递单调序号；同序号的其他视图只读取同一帧。播放、暂停、逐帧、循环与负速度都调用同一 seek 语义，失败不发布新时间。源会话由调用方关闭，倒退物理按下述播放器规则重演。

包内动画清单保留 source ID、来源路径、clip/stack 序号、原始绝对时间范围及源帧率。连续时间格式没有源帧率时，显式的预览步进帧率只决定逐帧步长，不重采样原曲线。枚举并不授予跨模型绑定能力；选择动作仍由实际播放器验证。PMM 多对象项目不伪装为单模型 clip。

`ScenePackagePlayback` 把同一套格式播放器接入统一会话，资产可共享，每个播放实例独占状态。两个视图来自同一个最终帧，源格式的镜头、材质与光影记录继续保存在类型化 details 中。包内动作通过来源 ID 和 clip/stack 序号选择；不同 glTF 文件具有不同节点编号域，不能直接串用。外部 VMD/VPD 使用 MMD 名称绑定，VRMA 使用人形重定向；尚无明确绑定的其他外部动画与 PMM 多对象播放会明确拒绝，不静默套用模型的原动画。

`YsmRuntime.physics()` 在启动时选择可用的自建 native Bullet；未安装、加载或 ABI/自检失败时回退 Chicory JVM/WASM。`javaOnly` 跳过全部 native 发现与加载，诊断只读取缓存的选择与回退原因。世界负责刚体、关节和软体求解，调用者显式控制固定步长。查询与绘制不能推进物理时间；已推进的 world 不跨 solver 自动切换。

可选 native Bullet 通过相同物理接口，Windows/Linux x64 的独立验证范围见[支持报告](../status/general-mesh-backend.md#验证证据与使用风险)。关节角度提取使用有来源与 hash 记录的 WASI-compatible float 数学函数，避免操作系统 CRT 的末位差异经关节与接触反复放大。刚体/关节结构通过一次 packed 调用构建。批量 pose、force、impulse、pin 和速度保护输入，以及刚体/软体输出，支持可复用 direct buffer；JNI 在访问前验证容量、标量对齐与全部输入。

MMD 四层程序按层号 sequential lerp/slerp，骨骼遮罩不屏蔽 morph/IK。冻结程序捕获 clip/配置/切换快照，采样与查询顺序无关；暂停保留 fade/transition 状态，淡出从当前有效权重开始。冻结求值复用私有控制器、默认通道和 clip 绑定缓存，在同步区内恢复层状态；各次结果仍持有不可变数据，跨线程和乱序查询不相互污染。播放器先求动画，再应用 VPD、显式 morph/IK 与组合骨骼旋转，最后经过 morph/IK/物理发布同一帧；setter 只标记待求值，不发布中间状态。

独立程序控制器缓存头/双眼/眨眼绑定，输出 XYZ 头旋转、限幅眼旋转与 sin 眨眼权重；追踪模式可让其他骨骼 owner 接管头眼。眨眼以显式逻辑帧 delta 推进，固定 seed/snapshot 可重放；空闲时释放对应 morph，避免持续覆盖动作表情。宿主输入与选择接线尚未完成。

正式 PMX/PMD 播放入口统一使用 packed 路径，复用 direct pose/impulse/pin 与 rigid/soft readback 缓冲，无 native 时沿用 WASM 的同一批量契约。传输层保留源标量，避免额外归一化四元数改变后续约束轨迹；刚体求解输出只在转为求值姿态时显式归一化。数值运算产生非有限状态时隔离 native world，后续操作拒绝；恢复只在候选 world 成功重放后交换。

关节开关、关联刚体碰撞与运动学过滤是独立的创建策略。RS 过滤先检查 group/mask，再排除恰好一方为运动学对象的碰撞对；仅允许空 world 选择策略。刚体临时转为运动学或恢复动态时重新加入宽相，重新评估碰撞关系。既有默认保持普通 Bullet 碰撞。

游戏宿主通过 `ScenePhysicsInput` 提供双精度实体原点、包含单位/反射/尺寸/实际朝向的模型放置矩阵、世界重力、邻近碰撞盒与流体区域。物理矩阵由实体渲染器建立，排除相机和 GUI 变换；第一/第三人称共享同一逻辑帧。`ScenePhysicsMotion` 按宿主时间计算线速度、线加速度、角速度及角加速度，匀速平移不产生持续惯性力。实例保留导数历史，切换动作播放器不重新建立运动基线；瞬移或超过 250 ms 的时间缺口重置动量。旧独立 `MmdPhysicsMotion` 不用于这条正式路径。

MMD 的刚体与软体接收重力、加速参考系惯性项、流体拖曳及视觉浮力；刚体还接收旋转惯性矩。方块 VoxelShape 的各 AABB 转为源空间八点凸包，进入真实 Bullet 接触求解；地形对象独立于来源刚体编号，按数量缩减/扩展并复用形状。源码自碰撞 mask 和混合运动学过滤不屏蔽地形接触。native ABI 6 / feature `0x100` 与 WASM ABI 5 使用同一环境策略头文件；安装并通过自检的 native 优先，旧 ABI 拒绝后在建世界前回退，运行中不迁移 solver。native 每帧一次 direct JNI 发布，live 不记录输入日志。

宿主每游戏 tick 采样邻近已加载方块与流体，不加载区块；采样半径最多八米，各类型最多 4096 个盒，超预算打印警告。水流使用 Minecraft 的流向和实际流体高度；流向单位向量按一米/秒的视觉输运策略使用，浮力按刚体中心/软体顶点所属流体区域求值，不是体积积分或完整水动力求解。空气不虚构风场，实体与攻击行为只通过实际运动轨迹进入惯性，不改 hitbox/伤害。VRM 保持自己的 Verlet 求解器，接入同一宿主导数和环境力，方块碰撞使用尾端球体投影及长度约束；来源的非竖直 gravityDir 分量保留。无来源物理的 glTF/FBX 不创建虚构刚体。

实时 MMD 和带宿主输入的 VRM 每次最多八个固定子步；预览 seek 保留完整来源重放。不保存游戏环境历史时拒绝带世界输入的倒退重放，清除输入后可使用独立预览。hostPhysics 参数保存在 sidecar，编辑器默认关闭物理。验收范围见 [支持报告](../status/general-mesh-backend.md#渲染与物理)。

MMD 变形能力独立于物理 solver 选择。Java 作为数值参考；可选 native 使用模型绑定的 direct 输入/输出和 Morph scratch，一个 JNI 调用处理整张顶点表，较大网格由最多四个长期 worker 分片。已发布帧复制拥有的数据，避免缓冲复用改变旧帧。会话由播放器关闭，候选物理重放复用同一变形会话。

宿主 MMD CPU 上传复用 staging 和动态 VBO 容量，同一帧、多材质和描边只上传一次顶点表，静态索引长期保留。满足 OpenGL 4.3、SSBO/dispatch/内存预算且无 PMX soft-body 时，实例可选择独立 compute 布局执行 BDEF/SDEF/QDEF 与绘制使用的稀疏 Morph。静态数据只初始化一次，每帧只上传 palette/morph 标量，输出 VBO 直接绘制；barrier 和小型状态回读确认完整结果。数值或设备失败后，从同一逻辑姿态走 CPU 回退，不能重新推进物理。程序、SSBO 槽位及范围恢复；实例关闭释放 compute 资源。`ysm.mmd.gpuSkinning=false` 可选择 CPU。设备与真实资产的验证范围见[验证范围](../status/general-mesh-backend.md#验证证据与使用风险)，不能据此宣称 shader-pack 或 Forge 世界验收。

预览快照保存输入历史，并在新世界完整重放后交换会话，以保留接触和软体求解历史。恢复成本随历史增长，输入日志有显式预算。实时世界可关闭重放历史，避免长期运行累积内存；此时快照接口明确拒绝调用。

VRM 的 SpringBone 使用独立托管 Verlet 求解器。球体与胶囊碰撞、中心空间惯性和世界空间外力按来源语义处理。VRM 1 使用显式 head/tail 对，允许链内存在中间节点；VRM 0 递归处理源子树，并为末端创建隐式尾端。尾端历史和模拟旋转构成完整的求解状态，可直接快照恢复；重复采样不推进时间。

VRM 播放器从确定性的时间源获取动画、视线、表情和约束结果，再推进独立弹簧实例。视线按静止姿态建立参考空间，旧版曲线按 Hermite 求值。分数时间只采样，倒退从零重放；前进求值失败时恢复原模拟历史和已发布帧。未被表情拥有的普通 morph 动画保留原轨道输出。

`MmdPlayback` 将不可变动画、骨骼调度与隔离物理世界绑定。倒退时从动画起点重建并重放整个实例，成功后才交换；前进工作量有显式预算。分数时间只采样动画并读取最后一个物理步的结果，不额外施加冲量。PMX/PMD 使用源模型单位，宿主在模拟外应用场景尺寸。软体按材质建立局部索引，动画固定点在下一物理步生效，模拟顶点与法线回写到拥有独立数据的输出帧。

正式 PMX/PMD 单 clip 播放使用 `MmdAnimationLayers.singleClip` 的冻结单层路径：一次性解析无歧义骨骼/表情名，复用单关键帧通道和重复来源时间的不可变采样；循环区间仍由原 `AnimationPlaybackRange` 决定。保持稀疏通道、作者顺序、重复通道覆盖和镜头/光影轨道，缺失或重名绑定保留原诊断。REST 不扩展为全骨架默认通道，YSM 姿态仍在来源采样后叠加。四层混合控制器不被强制引入单 clip 状态；该接入复用编译绑定/冻结采样机制，不表示游戏提供了四层混合编辑能力。

VMD 的灯光和自阴影轨道作为 `AnimationFrame` 通道输出。glTF 光源与相应节点全局变换可交给宿主扩展。内建效果绘制由[光影边界](../product-decisions/decisions/dual-model-backends.md#bcscene-light-shadow-extension-boundary)允许保留为后续工作。

FBX 每次求值同时输出材质、镜头和灯光数据，保留投影轴、光源衰减、阴影开关和原始属性。FBX 灯光强度仍使用源百分比归一值，不冒充 glTF 的物理单位。扩展可以通过节点变换与这些记录实现实际效果。

`CompatibilityReport` 区分读取、求值、绘制、外部效果与不支持。未知 glTF 扩展会保存原数据并报告；必要扩展尚未求值时，不能把场景声明为完整兼容。


## 宿主动作映射与分发

Mod 按模型内容身份保存动作别名。编辑器提供默认 YSM 动作名清单、搜索和自定义名称，将目标名绑定到具体来源 ID/clip 或 REST，并保存单次/循环模式；AUTO 表示删除显式绑定，恢复来源名称/文件名匹配和基础动作回退。保存采用临时文件替换，成功后才发布新版本；损坏配置保留原文件并阻止覆盖。编辑器拥有独立预览会话，与实体共享格式求值器。

动作轮盘和快捷键使用同一通用动作清单，包含已绑定的动作别名、来源动画的单次/循环项以及停止。服务器不解释客户端别名：客户端先将别名解析为来源动作 ID，服务器只允许模型 manifest 中声明的 ID。来源路径和 clip 决定基础身份，播放模式属于身份；每次点击附带新的请求序号用于重播，重复的权威状态刷新不重启动作。通用转换缓存使用新 profile，重建包含动作白名单的 manifest。

来源动画在自动匹配中优先于生成动作。实体自动状态覆盖空闲、走跑、蹲伏、游泳、飞行、滑翔、攀爬、跳跃、受伤、睡眠、激流和死亡；额外名称通过轮盘显式触发。移动打断沿用宿主已有锁定规则；单次有时长动作结束后恢复自动状态，零时长姿态保持到停止或打断。映射文件属于本地创作配置，额外动作分发使用已解析的来源身份；其他客户端不需要同名本地别名。自动状态映射配置本身不随网络分发。

Lib 将实时播放的来源时间和物理时间分开：来源时间按选定范围循环或停留末帧，MMD/Bullet 与 VRM 弹簧按单调递增的实例时间继续推进。切换动作创建新实例并从零开始；预览的显式跳转仍执行确定性重放。无 VMD 的 MMD 基础动作只对明确识别的躯干、上臂和大腿生成曲线，辅助骨、膝、脚踝及根骨不按名称子串误绑定，直接驱动腿部时关闭标准脚部 IK 控制器。这是基础回退动作，不是完整传统 YSM 曲线重定向。

独立 sidecar 创作工具和已求值 YSM 骨架绑定的职责、通道边界与宿主接线见[独立模型配置工具](scene-authoring-tools.md)。
