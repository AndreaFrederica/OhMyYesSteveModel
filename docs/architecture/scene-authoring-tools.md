# 独立模型配置工具

依据[双后端创作契约](../product-decisions/decisions/dual-model-backends.md#bcmesh-portable-authoring)，Oh My YSM Lib 的 SceneAuthoring 提供宿主无关的资产捕获、骨骼建议、校验、附加配置保存与无损场景包导出。CLI 和 Swing GUI 使用同一服务；Minecraft 页面属于主 Mod。配置字段见[逐模型配置标准](../standards/scene-model-profile.md)。

## 数据和保存

工具读取 PMX/PMD、glTF/GLB、VRM、FBX 和场景包；Blender 与 Unity 工程必须先经外部导出。捕获限定在模型目录内，不遍历符号链接，按文件字节和目录条目累计限制；默认累计 256 MiB、最多 100000 条目录项。当前依赖收集按相关扩展名进行，尚非全部格式的最小引用闭包，因此建议每个模型使用独立目录。

默认修改源文件旁的 `.omysm.json`，模型、纹理及动作文件保持原字节。写入校验源模型 size/mtime 和原配置内容，配置使用同目录临时文件原子替换；冲突保留用户文件。另存和场景包导出拒绝覆盖现有目标。包内嵌入完整配置，源文件与依赖按原字节保存；外部 sidecar 优先于内嵌配置。

## 预览和时间

游戏编辑器打开本地模型时同时保留 Catalog 相对路径与经过 custom 根校验的文件路径。保存只用文件路径，保存后等待新内容发布及应用只用原 Catalog 相对路径；不从 Windows 盘符、目录联接或符号链接解析后的物理路径反推 Catalog 身份，也不在 UI tick 中访问磁盘来重新计算路径。应用失败取消本次等待，将原始异常写入日志并显示在编辑器状态栏，已成功保存的附加配置不回滚。

GUI 在独立 worker 中加载、求值和绘制，EDT 负责交互；渲染不会锁住暂停或配置按钮。窗口可编辑尺寸、人体角色、源骨名、轴校正、动作来源、元数据和完整配置 JSON，支持撤销、保存冲突及错误堆栈。动作别名解析为实际来源路径和 clip，使用生产 ScenePackagePlayback 播放、暂停、逐帧和跳转。预览默认不创建物理世界，首版独立工具暂不提供物理开关。

相机使用静止可见网格的参考包围盒，动画运动不触发逐帧重新居中。独立窗口目前使用有深度缓冲的 CPU 几何/骨架诊断绘制，未共享游戏材质程序；源纹理、MToon/PBR/MMD 材质效果不能在此验收。它已能验证实际 VMD 与生成动作的骨骼和几何变化，不能声称原生 YSM 全曲线/Molang 已在独立工具求值。

## YSM 骨架绑定

SkeletonRetargeter 消费已求值的源局部刚性姿态和两个静止骨架，将源全局旋转变化转为目标局部差值。祖先控制骨参与求值，目标父级运动被扣除，目标静止骨长保留。位移差值来自动画位移通道，不从源静止骨长复制；未绑定祖先的位移可以传递，已由目标父骨承担的位移不再叠加。每骨轴校正与权重在同一换算中应用。

YsmSkeletonBinding 是 Lib 中的 BoneAttribute 适配器，按 YSM 的 ZYX Euler、X 位移符号及 MMD 的 Z 反射转换，并检查需要的源骨及祖先。当前目标是 PMX/PMD；影响绑定的缩放通道明确拒绝，材质、隐藏、表情不属于刚性姿态接口。MMD 播放器的绝对局部姿态覆盖位于来源动作/VPD 后、旋转叠加和 IK/物理前；解除覆盖恢复来源动作。直接驱动 FK 链时，只关闭与这些骨相交且未显式绑定控制骨的 IK 链。

游戏的源驱动会话借用配置指定的 MC player target 的 lease，默认使用内置 YSM 模型，运行原玩家控制器、Molang 和头部输入，不绘制源网格、不主动发送动作请求。有源骨绑定且状态未被显式覆盖时直接启用原生控制器；不会按同名 VMD 自动抢占。显式 VMD/VPD、生成动作、REST 和轮盘片段请求拥有动作选择权。普通原生状态变化保留播放器与物理世界。源驱动按宿主帧序号去重，源 lease 随目标换代释放。驱动会话复制玩家协议状态和手持物输入，使用独立动画时钟。额外原生动作轮盘、第一人称特殊输入、独立原生曲线预览及可重演物理输入历史仍需接通和验收，不能把刚性绑定接线表述为全部原生动画兼容。

任意 `bone:` 绑定与预设角色使用同一个刚性求值器；未绑定目标骨保持本地来源姿态并继承父骨，追加变换、IK 和物理由 MMD 求值器继续处理。同源多目标的权重是全局旋转差值权重，不等于自动 twist/swing 分解。参考姿态独立于轴校正，Lib 可根据实际 YSM 静止骨架与 MMD 臂段方向生成初值；Alt+Y 可调整每骨参考角度并预览完整 MMD 求值后的参考姿态，中间骨继承关系保持。该诊断预览不模拟整个 Minecraft 状态控制器。

SceneStateTransitions 按单调宿主时间选择一次性过渡片段；状态选择仍由主 Mod 决定。主 Mod 的实例持有 SceneFrameClock，在状态选择、源骨架输入和物理之前统一按 render sequence 去重，并保持采样时间高水位。同帧不同视图的 partial tick 可以不同，不能直接作为转换器的连续时钟；该宿主时钟不随动作切换重置，Lib 继续严格拒绝真正的倒退时间。CLI、桌面配置页和 Alt+Y 可保存来源片段过渡，状态映射和过渡共同校验源路径、clip 和有效时长。当前尚未实现 YSM 与 VMD 的跨后端姿态混合，独立界面仅能播放过渡来源片段，不能模拟全部 Minecraft 状态。

当前验证和缺口见[支持状态](../status/general-mesh-backend.md)。构建和调用见[构建指南](../build.md#独立模型配置工具)。

## 持物挂点

Lib 从 PMX/PMD、glTF/VRM 和 FBX 的最终骨架帧计算挂点；坐标转换使用共轭变换，消除源单位与手性对物品自身的影响。主 Mod 按玩家惯用手分配主副手，调用 Minecraft ItemInHandRenderer，并同步更新位置和法线矩阵。Alt+Y 提供左右挂点、开关、位置、角度、大小与第一人称模式，剑/盾用于检查挂点。

第一人称默认继续原版物品绘制。模型挂点模式由单次背景 pass 绘制，只有成功绘制背景并存在对应挂点才取消该手的原版 RenderHandEvent；隐藏模式取消两手物品。普通 YSM 专用第三方武器定位器不自动移植到通用骨架。

CLI 的 `calibrate-arms --rig` 与 GUI 的源参考骨架入口使用同一 Lib 校准器。源 rig JSON 为父在前的数组，每项 `{name,parent,pivot:{x,y,z},restRotation:{x,y,z}}`；pivot 为已完成 YSM 导入坐标转换的像素，restRotation 为原生求值器使用的 ZYX 弧度，parent=-1 表示根。此文件描述源静止骨架，不是 `.omysm.json` 的替代。`render --rig` 对 REST 播放器应用同一绑定器输出，能导出校准后的几何预览；不能与来源动画同时叠加。GUI 的参考姿态页可调整每骨参考角、校准和切换来源姿态，持物配置页保存同一附加配置。
