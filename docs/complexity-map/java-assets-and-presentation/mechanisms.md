# Java 资产与页面机制

本页定义 AP-01 至 AP-09 的机制行为、删除失败与证据入口。子系统范围见[总览](README.md)，证据边界见[证据、覆盖与根依据](evidence-and-scope.md)。

| ID / 机制 | 为什么存在、当前行为、直接删除的失败 | 上游原因 / 必要性 | 证据与未闭合部分 |
|---|---|---|---|
| AP-01 冻结实际解析闭包 | 解析分阶段执行，中途来源文件可能变化，前后读取可能得到不同内容。Archive 的借用视图还会被下一次读取覆盖。Capture（解析快照）深拷贝实际读取的字节并固定目录观察，scan/compile 复用同一 parser。直接重新读取来源会让身份认定与产物消费得到不同内容。 | `A-CAPTURE`；**Derived**。一致输入是产品义务，冻结后重跑 parser 是当前实现选择。详见：[capture 理由](../../architecture/model-management/design-rationale.md#capture-复用同一解析路径)。 | **Fact**。`ModelParser.capture` 等入口与对应测试断言修改后不回读、独立副本正确关闭。不保证整个可变文件系统在同一物理时刻快照。 |
| AP-02 分层准入与逐块验证 | 目录可见不等于内容有效。Metadata 前缀建立 identity 与 Manifest 描述，容器 reader 独占容器版本准入，schema reader 复用无状态开发版本门禁；实际 chunk 仍核对 size、hash 和适用解码。删除后，开发版本制品可能被稳定版策略误接纳，损坏或跨表示字节可能进入资源构造。 | `D-META`、`D-VERIFY`、`D-IDENTITY`、`D-FREEZE`；**Essential**。按需访问、精确表示与开发制品不可推断兼容均为产品契约。 | **Fact**。`VersionCompatibility` 等与对应测试覆盖两侧 marker、大小写、稳定版委托和 fail-closed。详见：[分层验证](../../architecture/asset-pipeline/container-and-validation.md)。版本门禁是纯函数；结构检查不能替代完整标准核对。 |
| AP-03 Raw PNG 的用途驱动重编码与失败回退 | 已有合法压缩表示（JPEG/WebP/AVIF 等）直接复用，只对 PNG 按用途策略重新编码。编码成功即采用结果，即使产物变大；仅可处理的 codec I/O 失败保留原图。删除格式门禁会重复处理既有压缩表示；删除失败回退会将可用输入变为转换失败。 | `D-IMAGE` 与 `A-IMAGE`；**Derived**。用途保真义务不可删；输入门禁、codec 参数与失败回退是可替换方案。legacy 解码期图片压缩另归 NR-17。 | **Fact**。`RawImageCompressor` 与对应测试断言复用、较大结果替换和失败回退。详见：[处理位置](../../architecture/asset-pipeline/conversion-and-export.md#图像处理的位置)。策略效果与成本证据见 [Q-04](open-questions.md#q-04)。 |
| AP-04 连续页面需求与迟到结果处置 | GUI 页面寿命短于共享资源。Screen 保存真实页面身份、前项持续与当前起点；内部重建交接同一意图，真实换页或关闭才撤需求。缺件且前项短暂时，当前连续超过 0.7 秒才提交同一 presentation action。同步与异步失败均为终态，迟到结果不能复活页面。删除会让短命页面发包、内部重建无法满足门槛或需求悬挂。 | `A-PAGE`、`A-CONTINUOUS-DEMAND`；**Derived**。产品要求过滤短命意图。 | **Fact**。`CatalogDemandTracker`、批量提交与失败入口、关页逻辑。详见：[页面 owner](../../architecture/client-presentation/README.md#页面与资源-owner)。Preview miss 仍归同一 page action；页面终态不回滚合法独立 cache。 |
| AP-05 Preview-first 与 hover-gated cache-only 3D | 卡片优先展示现成图片与 Ready 状态。仅连续 hover 同一模型超过 0.3 秒才尝试离线 3D；remote body miss 不发网络，也不污染正常加载。改用普通加载会让浏览驱动下载；构造即离线 bake 会让无需求卡片消耗资源。 | `A-PREVIEW`、`D-JOIN`、`A-CONTINUOUS-DEMAND`；**Derived**。展示体验与按需加载是产品义务；离线探测与 hover 状态是当前方案。 | **Fact**。`CatalogModelCardState`、预览渲染管理的离线与缓存入口。详见：[cache-only 边界](../../architecture/model-management/storage-and-cache.md)。真实 3D 体验收益和最坏 target 成本尚未量化。 |
| AP-06 转换 staging 与重开验证 | 转换产物不能直接视为成品。Raw/legacy 转换先形成独立 staging，验证 identity、逻辑 payload 和存储描述后才进入 converted object 或目录 candidate；失败清理本次半成品。只删门禁会将「转换过程成功」等同于「当前容器可读」，或暴露部分产物。 | `A-ONE-ARTIFACT`、`D-FREEZE`、`D-SOURCE`；**Derived**。统一出口带来产物交接；来源只读与完整内容是独立要求。 | 架构事实见[转换出口](../../architecture/asset-pipeline/conversion-and-export.md#发布与失败)与[单向投影](../../architecture/asset-pipeline/conversion-and-export.md#历史输入的单向投影)。验证入口在 `LegacyModelImporter.stage` 等。保留 staged 容器再读是当前策略。 |
| AP-07 实际来源准入与 schema 分离 | Schema reader 接受合法无图容器。Catalog 只对实际 direct 成品要求完整内嵌 preview；raw/builtin/legacy 内部结果允许缺图。来源由 resolver 调用链固定，不能由扩展名、`origin_ver` 或 cache 推测。删除分层会拒绝合法内部来源，或让缺图 direct 绕过产品门禁。 | `A-DIRECT-ADMISSION`、`D-SOURCE`；**Derived**。按来源准入是产品选择；单独 policy gate 是当前方案。 | **Fact**。`DirectContainerAdmission.requireEmbeddedPreview`、`ModelSourceResolver` 等。详见：[preview/export](../../architecture/asset-pipeline/conversion-and-export.md#preview-取得与显式-export)。完整来源矩阵与跨平台媒体尚未验证。 |
| AP-08 弱关联 preview cache 与完整 export | 内嵌图优先。独立图仅按 `ContainerId` 存储，坏读不删除，验证后原子覆盖。Client tick 的单一有限 operation admission 覆盖探测、加载、编码、存盘与 export；跨域 callback 只写容量为 1 的 owned fact slot，tick 观察终态后释放。服务端 export 由 server tick 接纳单项完整 worker。显式 export 复制已验证 stored chunks、保留 `ModelId` 与作者图、必要时嵌图并重算 `ContainerId`，重开 direct 验证后提交。删除独立 cache 会重复取得图片；将 cache 回写容器会制造身份循环；删除总 admission 会使 miss 或重复命令无界保留资源。 | `A-PREVIEW-CACHE`、`A-WORK`、`D-FREEZE`、`D-SOURCE`；**Derived**。日常不改容器、弱关联与完整 export 是产品边界；统一 admission 是满足主循环与有限在途义务的可替换方案。 | **Fact**。`ClientPreviewGenerator.tick`、`ModelExporter.export` 等。详见：[preview/export](../../architecture/asset-pipeline/conversion-and-export.md#preview-取得与显式-export)。Client 现为 16 active/32 pending/每 tick 4 次接纳；server export 为 8/16/4。局部测试覆盖 owner-pause、容量与终态；真实画面、命令与冷热成本未验证。 |
| AP-09 音频投影与双阶段验证 | Raw 与 legacy 都将受支持的单条 Ogg Vorbis/Opus 流投影为同一 current descriptor 与 direct chunk。Metadata admission 核对结构和媒体解释；目标声音取得或 materialization 再验证完整字节与 codec 闭包；export 原样复制并重开复验。删除统一 profile 会让 producer 与 consumer 对 codec、帧或存储形状产生分歧；将完整验证并入 catalog 浏览会预读全部声音。 | `D-SOUND`、`D-MIGRATION`、`D-JOIN`、`D-CHUNKS`；**Derived**。声音可播放、单向迁移与按需内容是产品义务；双阶段验证是当前方案。 | **Fact**。`RawModelAssembler`、`SupportedAudioProbe`、`LegacyModelImporter` 等。详见：[音频转换](../../architecture/asset-pipeline/conversion-and-export.md#音频内容转换)。独立 fixture 已覆盖 raw 目录/archive、current 导出重开与 legacy 投影；真实 v1/v2/v3 包装和游戏来源矩阵未验证。 |
