# Java 动画、绘制交接与扩展机制

本页定义 AN 机制的行为、删除失败与证据入口。子系统范围见[总览](README.md)，证据边界见[证据、覆盖与根依据](evidence-and-scope.md)。

共享依据：动画业务根见[实体隔离与动作次数](../../product-decisions/decisions/animation-isolation.md)、[采样](../../product-decisions/decisions/animation-sampling.md)、[controller 选择](../../product-decisions/decisions/bone-and-controller.md)。当前数据流见[动画架构](../../architecture/animation/README.md)与[帧执行](../../architecture/rendering/frame-execution.md)。

| ID / 机制 | 为什么存在、当前行为、直接删除的失败 | 上游原因 / 必要性 | 证据与未闭合部分 |
|---|---|---|---|
| AN-01 实体私有求值状态 | 同一 render target 的已解析 `IValue`（不可变 AST）与模型资源被各 entity 共享引用；每个 entity 持有自己的 `AnimationProcessor`、`MolangMemory`/`AnimationContext`、controller/player、ordinary `v`、random、physics、deferred 与骨骼状态。Roaming 是 `MolangMemory` 中的 scoped `Struct`，只有同一玩家主模型与第一人称手臂显式共享同一 struct。合并其他可变状态会让使用同一模型的实体互相改写动作或变量。 | `D-ENTITY`；**Essential**。已解析表达式与 catalog 可共享，动作与 instance state 不可共享。 | **Fact**。`AnimatableEntity`、`AnimationProcessor`、`MolangMemory` 等。详见：[实体 owner](../../architecture/animation/entity-and-frame-state.md#实体级所有权)。Roaming struct 由 `PlayerAnimatableCapability.getRoamingStruct`/`ClientRoamingSession` 按 model hash 提供；native 输出槽隔离不能替代求值状态隔离。 |
| AN-02 异步实体任务的串行与汇合 | 每实体至多一个 Future，新任务/消费前等待，另有全帧 task list。保留 worker 原地更新却删除汇合会使求值、extract、draw 或重绑重叠。 | `A-AN-01`；**Derived**。单实体顺序必需；本帧等待的调度方式可改变。 | **Fact**。`AnimationParallelTicker.scheduleAll/waitAll`、`CustomEntity.beginAsyncUpdate/awaitAsyncUpdate`。与主循环约束冲突见 [Q-01](open-questions.md#q-01)；不能仅删除 wait。显式 fences 单列 AN-13。 |
| AN-03 跳过求值时维持逻辑时间 | 距离/可见性限频后仍以累计时间推进，并区分逻辑推进与重复观察。把每次执行都当固定一步会使降频实体减速或重触发。 | `A-AN-03`；**Derived**。降频补偿状态依赖当前选择；实际呈现时间推进和重复观察不重复动作仍有独立义务。 | 行为与时间关系 **Fact**。距离/可见性直接减少求值次数，支持降低 CPU 工作量的 **Inference**；单纯修正动作语义不足以解释为何按距离减少执行。具体阈值的选择理由仍 **Hypothesis**，没有比较测量。`CustomEntity`、`AnimatableEntity`。整体表现与因果保持见 [O-07](open-questions.md#其他实现边界)。 |
| AN-04 多 pass 共用历史的输出分离与姿态恢复 | 常规 level 复用 canonical 输出，其他 context 可重新求值；coded 姿态修改在后续 pass 前恢复。删除协调会让某个 pass 的头部隐藏或姿态覆盖另一个 pass。 | `A-AN-02`；**Derived**。选择共用 controller 历史及骨骼输入后才需要跨 pass 恢复。 | **Fact**。`AnimatableEntity.update/extractRenderData`、`PlayerAnimatableCapability.recoverLastCodedAnimation`。详见：[输出与 context](../../architecture/animation/entity-and-frame-state.md)。Canonical pose 的复用不证明本次 draw metadata 仍正确。 |
| AN-05 动作与观察的阶段门禁 | `allowEmitting` 是求值窗口内的动作能力：controller 状态过渡、coded predicate、instruction keyframe 推进和显式注入在该窗口内置为 true，窗口结束即复位；GUI 预览实体由自身 predicate 决定窗口，默认 false。删除门禁会使同一次推进的动作随 pass 数增加。 | `D-EFFECT`、`A-AN-02`；**Essential** 指动作次数义务，具体能力表示可替换。 | 结构 **Fact**。`MolangContext.allowEmitting/setAllowEmitting`、`InstructionKeyFrameExecutor` 等。详见：[副作用阶段](../../architecture/animation/controllers-and-playback.md#副作用阶段)。外部入口（`ExecuteMolangEvent`、命令、GUI、player init/update 与 `ysm.sync`）经 `AnimatableEntity.executeMolangExp` 注入，按 pre/post 两阶段在 entity owner 上执行。当前没有失败 batch 收口，effect 在求值时直接提交。Forge once-only 仍待[动画问题](../../status/known-issues/animation.md)。 |
| AN-06 模型覆盖与内建动作桥接 | Hybrid 选择模型声明的 controller，未覆盖行为保留 coded/default。删除桥接会要求作品补写基础控制，或在补动画时丢失所选模型外观。 | `D-CONTROLLER`、`D-VANILLA-ACTION`、`D-AN-FALLBACK`；**Essential**。 | **Fact**。`HybridAnimationController` 与 controller collection。详见：[播放选择](../../architecture/animation/controllers-and-playback.md)、[默认回退](../../product-decisions/decisions/model-fallback.md)。多种 controller 不按实现类数重复计数。 |
| AN-08 现存并行动画的旋转混合补丁 | Parallel controller 仍启用 `blendRotation` 与 cached point accumulation；删除会改变其数值结果，但尚无受保护作品样本说明所需结果。 | 根理由缺口 `H-BLEND`；**Uncertain**。 | 存在性及源码注释所述「解决一个历史遗留问题而保留的动画混合」「旧版 blendRotation 只有高并行动画在用」为 **Fact**：`AnimationProcessor`、`CodedAnimationController`。原问题是否消失未知，不能标 Historical；兼容等级见 [Q-06](open-questions.md#q-06)。 |
| AN-09 生成依赖级兼容 checker | 编译期分析拥有代码与依赖，生成 checker/probe/manifest。直接删除生成端会使当前 runtime 因缺失 checker 跳过 handler。 | `A-AN-04`；**Derived**。 | **Fact**。`YsmExtensionProcessor.finishCompilation`、`CompatibilityAnalyzer.analyze`、`CheckerSourceGenerator`。详见：[扩展注册](../../architecture/integration/README.md#扩展兼容检查与注册)。可选降级能解释门禁，不能独自证明完整生成管线的收益，见 [Q-07](open-questions.md#q-07)。 |
| AN-10 先检查再加载及局部失败隔离 | Checker 接受前不初始化 handler；链接/构造/注册失败只跳过该 handler。删除前置隔离会让不兼容可选代码提前初始化或传播 loader 错误。 | `D-EXT`；**Essential**。具体反射结果协议由 AN-09 派生，隔离义务不依赖生成器。 | **Fact**。`YsmEventHandlerRegistration.prepare`、`YsmEventHandlerLoader.registerOne` 与对应测试。详见：[可选联动决策](../../product-decisions/decisions/integration-risk.md)。 |
| AN-11 连续顶点与宿主 consumer 的双路径 | 可识别布局走 direct，其他 consumer 走中间数组回放。删除 fallback 会丢失未知连续布局 consumer；删除 direct 则损失其优化。 | `A-NATIVE`；**Derived**。`D-OUTPUT` 约束路径等价，不强制两条路径的拓扑。 | **Fact**。`NativeRenderer.probeVertexConsumer/render`、`FallbackVertexWriter`。详见：[顶点输出](../../architecture/rendering/vertex-output.md)。吞吐差异未量化；完整路径的视觉等价仍待[实机验收](../../status/known-issues/rendering.md#待验证场景)。 |
| AN-12 成功后提交宿主输出 | Direct 先 reserve，native 成功才 advance；fallback 成功才回放。删除成功门禁会提交 native 失败前的部分输出。 | `D-HOST`、`A-NATIVE`；**Essential**。 | **Fact**。`NativeRenderer.render`、`VertexBufferAccessor`。详见：[输出契约](../../product-decisions/decisions/geometry-regions.md)。这不是完整事务：consumer 在回放途中抛错的隔离未核验，不能据此宣称所有 draw failure 已安全降级。 |
| AN-13 Future 外的显式内存 fences | 异步更新另调用 store/load fence。现有证据未证明这些 fences 解决了任务完成同步之外的独立可见性问题。 | 根理由缺口 `H-FENCE`；**Uncertain**。 | 存在性 **Fact**：`CustomEntity.beginAsyncUpdate/awaitAsyncUpdate`。必要性需先说明是哪一对未受任务完成关系覆盖的读写；不能把 AN-02 的数据竞争证明挪作其独立必要性证据。 |
| AN-19 Deferred capture 的求值快照与逆序排空 | `defer` 只登记已经求值的参数值，`AnimationContext` 按登记序号复用参数列表，随后在动画上下文 reset 点按登记逆序对当前 target 的 `defer` handler 重新执行，并只在该窗口内开放动作能力。直接保留 live 参数视图会在排空时读到被改写值；无限登记会扩大 entity 长期状态。 | `A-DEFER`；**Derived**，只为延后执行跨越 call-local 生命周期服务。 | **Fact**。`Defer`、`AnimationContext.defer/reset`、`CustomEntity.getMolangDeferHandler` 等。详见：[副作用阶段](../../architecture/animation/controllers-and-playback.md#副作用阶段)。参数按已求值对象保存，当前不限定为 F32 或有限数；capture 复用与逆序 drain 是当前实现，Forge 实机中的排空时机仍待验证。 |
| AN-20 模型声音触发与 host handoff | 主时间线把 keyframe、controller-state 与脚本声音路由到同一 entity/controller manager；模型声音每次独占 playback/decoder/cursor/candidate，通过 `AudioStream` offer，并以 channel attach/release ticket 闭合实际采用、拒绝、stop 与 callback 被跳过的终态。删除主时间线门禁会让多 pass 重复发声；把 future 完成当 adoption 会遗失未采用 stream；改走 complete-buffer cache 会复制宿主生命周期。 | `D-SOUND`、`D-EFFECT`、`D-HOST`；**Derived**。可观察声音、once-only effect 与局部失败是义务；ticket 是当前最小 handoff 方案。 | **Fact**。`SoundInstanceManager`、`CustomEntity.getSoundStream`、`CustomSoundInstance`、`HostAudioHandoff` 等。详见：[声音触发](../../architecture/animation/controllers-and-playback.md#声音触发与宿主播放)。局部测试覆盖两种 release/adoption 顺序和 stop-before-offer；真实 Forge/OpenAL adoption、设备 N+1 与音量尚未验证。 |
